## 1. Общие сведения

### 1.1. Основная информация

| Параметр | Значение |
| :--- | :--- |
| **Название проекта** | MyCreative 3D Scanner |
| **Тип проекта** | Интерактивное веб-приложение (Single Page Application) |
| **Назначение** | Демонстрация возможностей и управление процессом 3D-сканирования |
| **Команда разработчиков** | 4 человека |
| **Сроки реализации** | Сентябрь – Декабрь 2026 года |

### 1.2. Описание продукта

**MyCreative 3D Scanner** — это современное веб-приложение, представляющее собой интерактивную "витрину" для демонстрации и визуализации результатов 3D-сканирования. Продукт позволяет пользователям:

- Наблюдать 3D-модели в реальном времени с эффектами вращения
- Имитировать процесс сканирования с визуальной обратной связью
- Взаимодействовать с готовыми 3D-моделями (вращение, масштабирование)
- Скачивать результаты в форматах `.obj` и `.ply`

### 1.3. Актуальность

В современном мире 3D-сканирование перестало быть узкоспециализированной задачей и активно используется в промышленности, медицине, дизайне и культуре. Однако большинство существующих решений либо сложны в использовании, либо не имеют удобного веб-интерфейса для демонстрации и управления процессом. 

Данный проект призван создать интуитивно понятную платформу, которая делает процесс работы с 3D-сканером прозрачным, доступным и визуально привлекательным.

## 5. Функциональные требования

### 5.1. Структура страниц

Приложение реализовано в виде Single Page Application с двумя основными экранами. Переключение между экранами происходит без перезагрузки страницы.

**Главная страница (Витрина)** предназначена для демонстрации бренда и 3D-модели в режиме автоматического вращения. На странице размещается логотип с названием "MyCreative", 3D-сцена с объектом, который постоянно вращается, привлекательный заголовок с описанием проекта, кнопка навигации "Перейти в 3D-сканер" для перехода на страницу сканирования. Фон выполнен в темных тонах с космическими частицами, внизу страницы располагается footer с информацией о команде и годе разработки.

**Страница «3D Сканер»** является основным рабочим экраном для имитации сканирования и взаимодействия с 3D-моделями. В центре страницы расположено большое 3D-окно для рендеринга сцены. В нижней части находятся элементы управления: кнопка "Начать сканирование" для запуска имитации процесса, прогресс-бар для визуализации заполнения от 0 до 100%, текстовый статус сканирования, отображающий текущее состояние. После завершения сканирования появляется 3D-модель результата, активируется кнопка "Скачать результат" для скачивания файла в формате .obj или .ply. Также присутствует кнопка "На главную" для возврата на главную страницу.

### 5.2. Визуальные эффекты

В проекте реализованы следующие визуальные эффекты, создающие атмосферу высокотехнологичного 3D-сканера:

**Клубы дыма** — динамические частицы, создающие эффект дыма вокруг модели. Реализуется с помощью системы частиц Three.js с использованием 300-500 частиц, которые плавно движутся и рассеиваются.

**Лазерные лучи** — подсветка объекта по контуру, создающая атмосферу работы сканера. Реализуется с помощью Three.js Lines с эффектом пульсации прозрачности и цвета. Лучи располагаются вокруг модели снизу и по бокам, синхронизируются с анимацией модели.

**Пульсация модели** — плавное изменение размера и яркости модели в такт с эффектами. Реализуется в цикле animate() с использованием математических функций для создания волнообразного движения.

**Космический фон** — звездное небо с мерцающими частицами на заднем плане. Реализуется с помощью Three.js Points с анимацией вращения и изменения яркости.

**Цветовая схема** — фирменные цвета: голубой (#00d4ff) и фиолетовый (#7b2ffc), которые используются в интерфейсе и материалах 3D-сцены.

**Анимации UI** — плавные переходы, эффекты наведения кнопок, появление элементов с использованием CSS transitions и keyframes.

Все эффекты являются чисто визуальными и не требуют сложных вычислений на стороне сервера. Основная нагрузка ложится на GPU клиента через Three.js.

### 5.3. Логика Backend API

Серверная часть реализует минималистичный REST API для имитации процесса сканирования и выдачи файлов моделей.

**Запуск сканирования** — POST-запрос на эндпоинт `/api/v1/scan/start` инициирует имитацию процесса сканирования. В ответ сервер возвращает уникальный идентификатор сканирования и статус "processing".

**Получение статуса** — GET-запрос на эндпоинт `/api/v1/scan/status/{id}` позволяет получить текущий статус сканирования. В процессе выполнения возвращается прогресс в процентах. После завершения возвращается статус "ready" и ссылка на файл модели.

**Скачивание модели** — GET-запрос на эндпоинт `/models/{filename}` обеспечивает скачивание файла 3D-модели в форматах .obj или .ply.

Схема работы API: пользователь нажимает кнопку "Начать сканирование", frontend отправляет POST-запрос на сервер, получает идентификатор сканирования, затем каждые 500 миллисекунд опрашивает статус. Сервер имитирует прогресс от 0% до 100%, после чего возвращает статус "ready". Frontend загружает готовую модель из указанной ссылки и активирует кнопку скачивания.

### 5.4. Сценарии использования

**Просмотр витрины** — пользователь открывает главную страницу и наблюдает за вращающейся 3D-моделью, знакомится с брендом и описанием проекта.

**Переход в сканер** — пользователь нажимает кнопку "Перейти в 3D-сканер" и переходит на страницу сканера с 3D-окном.

**Запуск сканирования** — пользователь нажимает кнопку "Начать сканирование", запускается прогресс-бар, статус обновляется в реальном времени.

**Ожидание завершения** — пользователь наблюдает за заполнением прогресс-бара в течение 10-15 секунд, после чего появляется новая 3D-модель и активируется кнопка скачивания.

**Взаимодействие с моделью** — пользователь перетаскивает мышью по 3D-окну, модель вращается, масштабируется и перемещается с помощью OrbitControls.

**Скачивание результата** — пользователь нажимает кнопку "Скачать результат", начинается загрузка файла модели в формате .ply или .obj.

**Возврат на главную** — пользователь нажимает кнопку "На главную" и возвращается на главную страницу.

## 6. Техническая архитектура

### 6.1. Общая архитектурная схема

Система построена по принципу клиент-серверной архитектуры с четким разделением на frontend и backend компоненты.

**Клиентская часть (Frontend)** включает HTML/CSS/JS интерфейс, Three.js для 3D-рендеринга, API-клиент для взаимодействия с сервером и UI-компоненты (кнопки, формы). Клиент работает в браузере пользователя и отвечает за отображение интерфейса, рендеринг 3D-сцены и обработку действий пользователя.

**Серверная часть (Backend)** построена на Flask (Python) или Express (Node.js) и включает сервер, API endpoints и логику имитации сканирования. Сервер принимает запросы от клиента, обрабатывает их и возвращает необходимые данные.

**Хранилище** представлено статическими файлами моделей в форматах .obj и .ply, которые хранятся в файловой системе сервера и выдаются по запросу.

**Инфраструктура** включает GitHub для версионирования кода и совместной работы, а также хостинг на GitHub Pages или Render для размещения приложения в интернете.

### 6.2. Компоненты системы

**Клиент (Frontend)** — отвечает за отображение интерфейса, 3D-сцены и обработку действий пользователя. Использует HTML5, CSS3 и JavaScript (ES6). Взаимодействует с Backend через API.

**3D-Движок** — обеспечивает рендеринг 3D-сцены, эффекты и управление моделью. Использует Three.js (версия r128+). Работает в браузере на стороне клиента.

**API-Сервер** — обрабатывает запросы, имитирует сканирование и выдает модели. Использует Python/Flask или Node.js/Express. Принимает запросы от клиента по протоколу HTTP.

**Хранилище моделей** — обеспечивает хранение 3D-моделей для выдачи пользователям. Использует файловую систему сервера. Доступно через API.

**Система контроля версий** — управляет кодом, документацией и совместной работой. Использует Git и GitHub. Доступна всем разработчикам.

**Хостинг** — размещает приложение в интернете для доступа пользователей. Использует GitHub Pages для статики и Render/PythonAnywhere для бекенда.

### 6.3. Потоки данных

**Загрузка главной страницы:** пользователь открывает index.html, браузер загружает HTML, CSS и JavaScript, JavaScript инициализирует Three.js сцену, загружается модель для витрины и запускается анимация вращения.

**Запуск сканирования:** пользователь нажимает "Начать сканирование", frontend отправляет POST-запрос на `/api/v1/scan/start`, backend создает запись сканирования и возвращает ID, frontend начинает опрос статуса каждые 500 миллисекунд, backend имитирует прогресс от 0% до 100%, при достижении 100% backend возвращает статус "ready", frontend загружает новую модель из `/models/result.ply` и активирует кнопку "Скачать результат".

**Скачивание результата:** пользователь нажимает "Скачать результат", frontend отправляет GET-запрос на `/models/result.ply`, backend возвращает файл модели, браузер начинает загрузку файла.

### 7.1. Полный стек технологий

**Дизайн** реализуется с помощью Figma для создания макетов интерфейса и Adobe Illustrator для разработки логотипа. Эти инструменты позволяют создать качественный визуальный концепт и брендинг проекта.

**Frontend** построен на HTML5 для структуры веб-страниц, CSS3 (Flex/Grid) для стилизации и адаптивности, JavaScript (ES6+) для клиентской логики. Для 3D-графики используется Three.js (версия r128+), который обеспечивает рендеринг 3D-сцены, эффекты и управление моделями.

**Backend** реализован на Python 3.10+ с использованием фреймворка Flask 2.3.3 для серверной логики. В качестве альтернативы может использоваться Node.js 16+ с Express 4.x. Для взаимодействия с фронтендом используется библиотека Flask-CORS.

**Версионирование** обеспечивается Git для контроля версий и GitHub для хостинга репозитория и совместной работы.

**Хостинг** осуществляется с использованием GitHub Pages для статического хостинга frontend-части и Render или PythonAnywhere для хостинга backend-части.

**Документация** ведется в формате Markdown для README, ТЗ и API документации.

### 7.2. Зависимости Backend

Для работы серверной части на Python/Flask требуются следующие зависимости: Flask версии 2.3.3, Flask-CORS версии 4.0.0 для обработки кросс-доменных запросов, python-dotenv версии 1.0.0 для управления переменными окружения. Все зависимости указываются в файле requirements.txt.

### 7.3. Требования к окружению

Для разработки и запуска проекта необходимо наличие Python версии 3.10 или выше (либо Node.js 16+ при использовании альтернативного бекенда), Git версии 2.30 или выше для работы с репозиторием, а также современный браузер (Google Chrome 90+, Microsoft Edge 90+ или Mozilla Firefox 88+) для тестирования и использования приложения.
